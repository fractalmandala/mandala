Foundations/Tokens

Color tokens

Six semantic surfaces keep the docs shell quiet in light mode and dense in dark — the same contract you’ll bind in SvelteKit layouts.

Updated Aug 5, 2026·Reading time · about 6 min

fractaldesign treats the reading surface as a product surface. Sidebars stay slightly tinted, the article column sits on pure surface, and the right rail reuses the page background so hierarchy comes from structure — not decoration.

Accent is brand green #0A7828 — reserved for selection wash, active nav, links in prose, and at most one primary accent cue per viewport. Selected nav uses a soft mix of accent into surface — never a solid block.

Token model

Bind these six variables once at the document root. Everything else — hover washes, code panels, selected rows — is derived with color-mix() so dark mode only needs a second root map.

tokens.css 
/* light · soft product chrome */
:root {
  --bg:      oklch(97.5% 0.004 95);
  --surface: oklch(100% 0 0);
  --fg:      oklch(22% 0.014 250);
  --muted:   oklch(50% 0.012 250);
  --border:  oklch(90% 0.006 95);
  --accent:  #0A7828;
}

Three-column shell

The layout is a sticky grid: sidebar (nav), main (prose), toc (on this page). Below 1100px the TOC drops and the left nav collapses into a drawer opened from the menu control.

Sidebar behavior

Group links with mono uppercase labels. Active items use the soft green select wash. On tablet and mobile the sidebar is off-canvas by default and slides in over a scrim. Nested items indent rather than opening heavy tree chrome.

Reading column

Cap measure near 68ch. Headings use the display stack with tight tracking. Code lives in bordered panels with a utility bar for language tabs.

Theme toggle

Persist data-theme on <html>. Default to system preference on first visit, then honor the user’s last choice. Primary actions invert with the foreground token so they stay high-contrast in both themes.

GET /api/theme local only · no network

Button

Primary, secondary, and ghost actions sharing one height, radius, and focus ring. Primary uses foreground ink so it survives both themes.

Usage

Button.sveltecopy
<!-- primary action · one per viewport -->
<button class="btn btn-primary">Read docs</button>
<button class="btn btn-secondary">GitHub</button>
