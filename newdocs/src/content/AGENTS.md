This file is the **engine-agnostic regeneration contract** for the `repowiki/`
knowledge base. Any agent (Claude Code, Codex, Qoder, Cursor, a plain LLM with
file tools) can read this file and regenerate or maintain the wiki without any
vendor-specific plugin. There is no qoder-only dependency — `repowiki-main/` is
a thin Go launcher and nothing here requires it.

## Contract (short version)

1. **Every `.md` file has YAML frontmatter.** No exceptions.
2. **No H1 at the top of any document.** The title lives in frontmatter only —
   never add a `# Title` line after the frontmatter; it would duplicate the
   title when rendered. Section headings start at `##`.
3. **All file and folder names are kebab-case.** Tool markers (`_module.yaml`,
   `_index.yaml`, `wiki_plan.yaml`) are exempt — they are tool state.
4. **Every folder has `INDEX.md`** — a `type: catalog` page listing subitems as
   a linked list with file-relative links.
5. **`wiki/cards/` and `wiki/concepts/` are flat** — top-level `.md` files
   only, never subfolders. Module trees from exports are flattened into
   prefixed filenames (`fractal-monorepo-packages-overview.md`).
6. **`wiki/TAGINDEX.md`** — a generated `type: catalog` page listing every tag
   used across `wiki/cards` + `wiki/concepts`, with file-relative links to the
   files carrying each tag. Regenerated by `scripts/generate-index.py`; never
   hand-edit.
7. **Linking is file-relative markdown only** — `[label](target.md)` computed
   from the linking file's folder. No leading slashes, no `file://`, no
   `[[wikilinks]]`.
8. **`path` values are repo-relative** (`packages/fractalsvelte`), never
   absolute.
9. **The wiki is updated ONLY on command.** There is no auto-update on git
   commits. If you are asked to update the wiki, do it explicitly; never
   regenerate it as a side effect of another task.

## Layout

```
repowiki/
  README.md                  # human entry point
  AGENTS.md                  # this file — the regeneration contract
  wiki_plan.yaml             # neutral YAML data (scope excludes + notes)
  meta/                      # exporter state JSONs + yaml indexes (gitignored, never hand-edit)
  wiki/
    TAGINDEX.md              # generated tag -> files index (type: catalog)
    cards/                   # all knowledge cards — FLAT, one schema, no subfolders
    concepts/                # module-level overviews — FLAT (type: concept)
  repo/                      # monorepo-level docs (generated + curated guides)
  projects/
    apps/                    # projects under apps/
    packages/                # projects under packages/
    sites/                   # projects under sites/
    other/                   # anything not in the three above
```

## Frontmatter schemas

### wiki/cards + wiki/concepts

```yaml
---
title: fractalsvelte
description: SvelteKit component library — props-based customization
tags: [package, sveltekit]
type: card                 # card | concept
module: packages/fractalsvelte   # path-based, repo-relative
path: packages/fractalsvelte     # repo-relative, no absolute prefix
created: 2026-08-04
updated: 2026-08-04
source_files: []           # OPTIONAL — provenance on generated cards only
---
```

No `relates_to` — relationships live in the body as file-relative links.

### repo/ + projects/ (all pages)

```yaml
---
title: Advanced Topics
description: Tauri backend structure, capabilities, GGUF serving
type: item                 # overview | item | catalog | knowledge
---
```

`type` vocabulary: `overview` = folder landing page · `item` = atomic doc ·
`catalog` = index/listing (INDEX.md) · `knowledge` = cross-cutting concept
(rare; prefer wiki/cards).

## Commands (agent vocabulary)

The user triggers wiki work with these phrases. Map them to the flows below.

| User says | Flow |
|---|---|
| `generate fresh repowiki` | Run `scripts/generate-repo.py` to scaffold `repo/` from `meta/*.json`, then regenerate/refresh `wiki/cards`, `wiki/concepts`, `repo/`, `projects/` from source, then `generate-index.py` + `validate.py`. |
| `update <path> in repowiki` | Run `scripts/affected.py <path>` to find pages referencing that file/folder, read the source, update ONLY those pages per this contract, then `generate-index.py` + `validate.py`. |
| `check and fix frontmatter` | Run `scripts/fix-frontmatter.py --check`, then `--fix` to repair (missing keys, leading H1, kebab names). |
| `check and fix index files` | Run `scripts/generate-index.py` (rebuilds every INDEX.md + TAGINDEX.md), then `validate.py`. |
| `check and fix file refs` | Run `scripts/fix-file-refs.py --check`, then `--fix` (converts `file://` and absolute-path refs to readable inline-code paths), then `validate.py`. |

### Flow: fresh generation

1. Read this file + `README.md` + `meta/*.json` state.
2. `python3 repowiki/scripts/generate-cards.py` — scan `apps/`, `packages/`,
   `sites/` (honoring `wiki_plan.yaml` scope exclusions) and emit one flat card
   per module + module concepts.
3. `python3 repowiki/scripts/generate-repo.py` — scaffold `repo/` from
   `repowiki-monorepo-metadata.json`.
4. `python3 repowiki/scripts/generate-projects.py` — scaffold `projects/` from
   `meta/site-*-metadata.json`.
5. Agent pass: read the actual source for each module and fill in the
   `<!-- TODO: agent step -->` bodies with real content, per the schemas.
6. `python3 repowiki/scripts/generate-index.py`
7. `python3 repowiki/scripts/validate.py`

### Flow: targeted update (`update <path>`)

1. `python3 repowiki/scripts/affected.py <path>` — find affected pages.
2. Read the changed source file/folder.
3. Update ONLY the affected pages (plus INDEX.md/TAGINDEX.md if names or tags
   change). Preserve frontmatter, links, kebab-case.
4. `python3 repowiki/scripts/generate-index.py`
5. `python3 repowiki/scripts/validate.py`

## Regenerating

### Full regeneration from `meta/`

The exporter state in `meta/*.json` is the machine-readable source of truth
(78 repo items + 4 site trees). A deterministic generator may rebuild
`repo/` from `meta/repowiki-monorepo-metadata.json` — one kebab-case page per
`wiki_items` entry, with `title`/`description` from the item and `type: item`.

### Incremental update

1. Read `wiki_plan.yaml` for scope exclusions and notes.
2. Detect changed source files (git diff).
3. Find affected wiki pages (pages whose `<cite>`/source_files reference the
   changed files, or heuristic folder match).
4. Update ONLY the affected pages. Preserve frontmatter, relative links,
   kebab-case, and INDEX.md catalogs.
5. Never hand-edit `meta/`.

### New cards / concepts

- **Card**: atomic note about one module, concept, or external dependency.
  Place directly under `wiki/cards/` — the folder is flat, no subfolders.
  Write full frontmatter per the schema.
- **Concept**: module-level overview (`apps/`, `packages/`, `sites/`) →
  `wiki/concepts/` with `type: concept`. Also flat.
- Link to related pages from the body with file-relative links.
- After adding/removing cards or tags, re-run `generate-index.py` (refreshes
  `INDEX.md` catalogs + `TAGINDEX.md`).

## Rules of thumb

- Prefer linking to the closest existing page over creating a new one.
- Keep `created`/`updated` as ISO dates (`YYYY-MM-DD`).
- Never emit a top-level `#` heading — the frontmatter `title` is the heading.
- If a page moves, update every incoming link and its folder's INDEX.md.
- Generated trees may be re-exported at any time — never hand-edit inside
  `meta/`, and treat `repo/` + `wiki/cards` module trees as regenerable (your
  edits there may be overwritten by the next export; curated additions belong
  at the tree roots or in new files).

## Maintenance scripts

- `scripts/generate-index.py` — regenerate every INDEX.md + wiki/TAGINDEX.md
  (neither emits an H1).
- `scripts/validate.py` — enforce the contract above (including flat
  cards/concepts + TAGINDEX coverage); run after any regeneration or
  hand-edit.
- `scripts/fix-frontmatter.py` — `--check` reports frontmatter violations,
  `--fix` repairs them (missing keys, leading H1, kebab names).
- `scripts/affected.py <path>` — list wiki pages referencing a source file or
  folder (for targeted updates).
- `scripts/generate-repo.py` — deterministic `repo/` scaffold from `meta/*.json`
  (never overwrites existing pages).
- `scripts/generate-cards.py` — fresh-build card generator: scan the source
  (`apps/`, `packages/`, `sites/`) and emit flat cards + concepts.
- `scripts/generate-projects.py` — scaffold `projects/` from `meta/site-*.json`.
- `scripts/port-old.py` — one-shot content migration from `repowiki-old/` into
  the current layout: ports matched `repo/` + `projects/` pages and all
  `wiki/cards` + `wiki/concepts`, rewriting every relative link for the new
  depth (run with `--dry-run` to preview; reads only from `repowiki-old/`, so
  it is safe to re-run).
- `scripts/fix-file-refs.py` — `--check` reports `file://` and absolute-path
  refs in bodies, `--fix` converts them to readable inline-code paths (keeps
  anchors; strips `file://`/`/Users/...` prefixes).
