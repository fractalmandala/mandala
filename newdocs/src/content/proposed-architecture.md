Single source of truth for the `repowiki/` layout, file schema, and linking rules.
Every `.md` file in this tree must conform. Any agent (Claude, Codex, Qoder,
Cursor, …) can read this file and regenerate or maintain the wiki.

## Global rules

1. **Every `.md` file has YAML frontmatter.** No exceptions — not even INDEX files.
2. **No H1 at the top of any document.** The title lives in frontmatter only;
   never duplicate it with a `# Title` line. Section headings start at `##`.
3. **All file and folder names are kebab-case.** Tool markers `_module.yaml`,
   `_index.yaml`, `wiki_plan.yaml` are exempt (they are tool state, not content).
4. **Every folder has `INDEX.md`** — a `type: catalog` page listing its subitems
   as a linked list.
5. **`wiki/cards/` and `wiki/concepts/` are flat** — top-level `.md` files
   only, no subfolders. Exported module trees are flattened into prefixed
   filenames (`fractal-monorepo-packages-overview.md`); single-card folders
   collapse to their basename (`business-glossary/` → `business-glossary.md`).
6. **`wiki/TAGINDEX.md`** — generated `type: catalog` page listing every tag
   used across `wiki/cards` + `wiki/concepts`, each with file-relative links to
   the files carrying it. Regenerated by `scripts/generate-index.py`.
7. **Linking is file-relative markdown only.** `[label](target.md)` or
   `[label](subdir/target.md)` — computed from the linking file's location. No
   leading slashes, no `file://`, no `[[wikilinks]]`.
8. **`path` values are repo-relative** (`packages/fractalsvelte`), never absolute.

## Frontmatter schema

### wiki/cards + wiki/concepts

```yaml
---
title: fractalsvelte
description: SvelteKit component library — no Tailwind, props-based customization
tags: [package, sveltekit, component-library]
type: card                 # card | concept
module: packages/fractalsvelte   # path-based, repo-relative location
path: packages/fractalsvelte     # repo-relative, no absolute prefix
created: 2026-08-04
updated: 2026-08-04
source_files: []           # OPTIONAL — provenance only, kept from generated cards
---
```

- `relates_to` is removed. Relationships are expressed via file-relative links in the body.
- `source_files` is optional provenance carried over from the generated-card export; hand-written cards omit it.

### repo/ + projects/ (all pages)

```yaml
---
title: Advanced Topics
description: Tauri backend structure, capabilities, GGUF serving
type: item                 # overview | item | catalog | knowledge
---
```

`type` vocabulary:

| type | meaning |
|---|---|
| `overview` | folder landing page (each folder's `INDEX.md` can also be `catalog`) |
| `item` | an atomic documentation page |
| `catalog` | an index/listing file (`INDEX.md`) |
| `knowledge` | cross-cutting concept (rare; prefer wiki/cards) |

## INDEX.md format

Every folder gets an `INDEX.md`, `type: catalog`, containing a linked list of
its direct subitems (folders and files), file-relative. No H1 heading — the
frontmatter `title` is the heading:

```markdown
---
title: Cards
description: All knowledge cards in the wiki
type: catalog
---

- [fractalsvelte](fractalsvelte.md)
- [shradhapp](shradhapp.md)
- [Card Subfolder](subfolder/INDEX.md)
```

## Tag index (TAGINDEX.md)

`wiki/TAGINDEX.md` is a generated catalog. Format (no H1 — title in
frontmatter, section headings at `##`):

```markdown
---
title: Tag Index
description: Every tag used across wiki cards and concepts
type: catalog
---

## sveltekit

- [fractalsvelte](cards/fractalsvelte.md)
- [Shradhapp](cards/shradhapp.md)
```

Tags are read from the `tags:` frontmatter of every `wiki/cards/*.md` and
`wiki/concepts/*.md` (INDEX.md files carry no tags). Tag strings are listed
verbatim; files under each tag are sorted by path.

## Regeneration contract (any agent)

1. Read this file, `README.md`, and the `meta/*.json` state.
2. Scan the repo, honoring the scope rules in `wiki_plan.yaml`.
3. Update or create pages under `wiki/`, `repo/`, `projects/` per the schemas
   above. Never hand-edit `meta/` (tool state).
4. Preserve frontmatter, file-relative links, kebab-case, and INDEX.md catalogs.
5. A deterministic generator (`scripts/generate-repo.py`, to be written) rebuilds
   `repo/` from `meta/repowiki-monorepo-metadata.json` when needed.
