A knowledge base distilled from the entire `mandala` monorepo. Markdown is the
source of truth. The full contract — layout, frontmatter schemas, linking rules,
and regeneration — lives in [AGENTS.md](AGENTS.md) and
[proposed-architecture.md](proposed-architecture.md); this file is the human
entry point.

> **New here?** Start with the **[User Guide](user-guide.md)** — it explains
> how to update, regenerate, fix, and maintain the wiki in plain language.

## Layout

```
repowiki/
  README.md                  # this file
  AGENTS.md                  # any-agent regeneration contract
  proposed-architecture.md   # finalized architecture spec
  wiki_plan.yaml             # build steering (scope excludes + notes, tool config)
  wiki/                      # hand-authored knowledge
    TAGINDEX.md              # generated tag -> files index
    cards/                   # all knowledge cards — flat, one schema, no subfolders
    concepts/                # module-level overviews — flat (type: concept)
  repo/                      # monorepo-level docs
    architecture-and-design/ api-reference/ backend-development/
    desktop-applications/ documentation-sites/ shared-packages/
    docs-scaffolding/        # curated docs-tooling guides
    sveltekit-master-builder/ # curated SvelteKit guides
    getting-started.md project-overview.md development-workflow.md advanced-topics.md
  projects/                  # per-project docs, grouped by repo role
    apps/                    # projects under apps/
    packages/                # projects under packages/ (e.g. fractal-agentic)
    sites/                   # projects under sites/ (fractaldharma, fractalhome, ...)
    other/                   # anything not in the three above
  meta/                      # tool state — gitignored, never hand-edit
```

## Updating (manual only — no auto-update)

The wiki is updated **only when you ask**. There is no post-commit hook and
no auto-regeneration. Tell any agent one of these:

| You say | Agent runs |
|---|---|
| **generate fresh repowiki** | `generate-cards.py` (cards from source) + `generate-repo.py` (repo from meta) + `generate-projects.py` (projects from site meta) + agent content pass, refresh indexes, validate |
| **update `<path>` in repowiki** | `scripts/affected.py <path>` → update only affected pages, refresh indexes, validate |
| **check and fix frontmatter** | `scripts/fix-frontmatter.py --check` then `--fix` |
| **check and fix index files** | `scripts/generate-index.py` then `validate.py` |

## Rules

1. **Every `.md` file has YAML frontmatter.** Cards/concepts use the rich
   schema (`title/description/tags/type/module/path/created/updated`, optional
   `source_files`); repo/projects pages use `title/description/type`.
   `relates_to` is gone — relationships are file-relative body links.
2. **No H1 at the top of any document.** The title lives in frontmatter only;
   a duplicate `# Title` line would render twice. Section headings start at `##`.
3. **Kebab-case everywhere.** Tool markers (`_module.yaml`, `_index.yaml`,
   `wiki_plan.yaml`) are exempt.
4. **Every folder has `INDEX.md`** (`type: catalog`) listing its subitems.
5. **`wiki/cards/` and `wiki/concepts/` are flat** — top-level `.md` files
   only, no subfolders; export module trees are flattened into prefixed
   filenames.
6. **`wiki/TAGINDEX.md`** lists every tag used in `wiki/` with links to the
   files carrying it; regenerated by `generate-index.py`.
7. **File-relative markdown links only** — no leading slashes, no `file://`,
   no `[[wikilinks]]`.
8. **`path` values are repo-relative** (`packages/fractalsvelte`), never
   absolute; external corpora keep `module: external/…` with no `path`.

## Maintenance scripts

- `scripts/generate-index.py` — regenerate every `INDEX.md` + `wiki/TAGINDEX.md`
  (neither emits an H1).
- `scripts/validate.py` — enforce the full contract (frontmatter, no leading
  H1, kebab-case, INDEX coverage, flat cards/concepts, TAGINDEX coverage,
  schemas, banned patterns). Run it after any regeneration or hand-edit.
- `scripts/fix-frontmatter.py` — `--check` / `--fix` frontmatter per layer
  schema.
- `scripts/affected.py <path>` — find wiki pages referencing a source path.
- `scripts/generate-repo.py` — deterministic `repo/` scaffold from `meta/`.
- `scripts/generate-cards.py` — cards/concepts from a live source scan.
- `scripts/generate-projects.py` — `projects/` scaffold from `meta/site-*.json`.

## repowiki-main

The Go CLI in `repowiki-main/` is a thin launcher for the same flows — see its
README. It defaults to manual mode (no hook, no auto-commit); auto-update on
git commits is opt-in via `repowiki enable --auto` and off by default.
